# Backend Coding Rules

## Package Layout
```
com.docint/
├── config/        beans, thread pools, external client config
├── security/      JWT provider, filter, UserDetailsService
├── controller/    REST entry points only
├── service/       business logic
│   └── storage/   StorageService interface + 4 implementations
├── agent/         Spring AI @Tool definitions
├── entity/        JPA entities
├── repository/    Spring Data JPA interfaces
├── dto/
│   ├── request/   inbound request bodies
│   └── response/  outbound response bodies
├── exception/     custom exceptions + GlobalExceptionHandler
└── util/          stateless helpers (FileValidationUtil, HashUtil)
```

## Controller Rules
- Controllers only: parse request → call one service → return DTO
- Never inject or call repositories directly from a controller
- Use `@Valid` on request bodies; validation errors are handled by GlobalExceptionHandler
- Return `ResponseEntity<T>` with explicit status codes
- Endpoints prefixed: `/api/documents`, `/api/chat`, `/api/admin`, `/api/auth`

## Service Rules
- One `@Service` class per business capability — no "God services"
- Services may call other services; they own the transaction boundary (`@Transactional`)
- Services never return JPA entity objects to controllers — always map to DTOs first
- No raw JSON manipulation in services; use typed DTOs and Jackson ObjectMapper

## Async Rules
- All long-running operations (embedding, ingestion) use `@Async("ingestionExecutor")`
- Async methods must return `CompletableFuture<T>` or `void`
- Thread pool is configured in `AppConfig` as `ingestionExecutor` (5 threads)
- Always catch exceptions inside `@Async` methods and update entity status to FAILED

## Entity Rules
- Entities use `@Builder`, `@NoArgsConstructor`, `@AllArgsConstructor` from Lombok
- No business logic inside entity classes — they are pure data containers
- All primary keys are `UUID` generated by `gen_random_uuid()` at DB level
- Use `@CreationTimestamp` / `@UpdateTimestamp` for audit fields
- Never expose entities through the API — always use DTOs

## DTO Rules
- Use Java records for immutable response DTOs where possible
- Request DTOs use regular classes with `@Valid` constraint annotations
- DTOs live in `dto/request/` and `dto/response/` sub-packages

## Exception Handling
- Every business exception extends a custom base: `DocumentProcessingException`, `StorageException`, `ResourceNotFoundException`
- `GlobalExceptionHandler` (@RestControllerAdvice) maps every exception to a typed error response — no raw 500s
- Never swallow exceptions silently; log at WARN or ERROR level before re-throwing

## SOLID Application
- **S**: One class, one responsibility (IngestionService orchestrates; it does not embed or parse itself)
- **O**: StorageService is an interface — add new providers by adding a class, not editing existing ones
- **L**: All StorageService implementations are substitutable; no `instanceof` branching in service code
- **I**: @Tool interfaces are narrow — DocumentSearchTool only searches, does not mutate
- **D**: Services depend on interfaces (`StorageService`), not concrete implementations

## Validation
- File upload: validate MIME type via Apache Tika detection (not file extension)
- File size: check before reading content (reject > 50MB early)
- UUIDs from path variables: Spring validates format; service validates existence via `orElseThrow`
- Never trust user-provided category strings without checking against allowed values

## Null Safety
- Use `Optional.orElseThrow(ResourceNotFoundException::new)` — never `Optional.get()`
- Annotate non-null parameters with `@NonNull` (Lombok)
- Return empty collections, not null, from list methods

## Flyway
- Migration files are **immutable** — never edit a committed V*.sql file
- Additive changes only: add columns with defaults, never drop or rename in place
- Test migrations run against the Docker Compose Postgres before committing

## Logging
- Use SLF4J (`LoggerFactory.getLogger`) — never `System.out.println`
- Log at DEBUG for pipeline steps, INFO for major state changes, WARN for recoverable errors, ERROR for failures
- Never log API keys, passwords, or file content

## Security
- Secrets come from environment variables only — never hardcoded or in application.yml values
- MIME type whitelist: PDF, DOCX, XLSX, PPTX — reject all others with 400
- JWT secret must be ≥ 32 characters; validated at startup
- Admin-only endpoints secured with `hasRole("ADMIN")` in SecurityConfig
